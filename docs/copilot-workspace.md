## Как зайти в Copilot Workspace

Есть два основных способа открыть Copilot Workspace — через репозиторий и через issue.

### Через репозиторий

1. Перейдите на [страницу репозитория](https://github.com/maksimmishakov/mismatch-recruiter) на GitHub.
2. В верхней части страницы нажмите кнопку **Copilot**.
3. Выберите пункт **Open Workspace** (или аналогичный) — откроется веб-окно Copilot Workspace.
4. В открывшемся окне опишите задачу обычным текстом.

   > **Пример:** `Добавить endpoint /metrics в FastAPI с Prometheus-метриками`

### Через issue

1. Откройте нужный [GitHub issue](https://github.com/maksimmishakov/mismatch-recruiter/issues) в репозитории.
2. Нажмите кнопку **Open in Workspace** на странице issue.
3. GitHub откроет Copilot Workspace, уже привязанную к этому issue.
4. Workspace автоматически возьмёт заголовок и текст issue как исходную задачу и начнёт строить спецификацию.

> **Альтернатива:** Откройте [Copilot Workspace Dashboard](https://copilot-workspace.githubnext.com), выберите **New Session** и укажите репозиторий и задачу вручную — это аналог черновика issue.

## Первичная настройка сессии

После входа в Workspace выполните следующие шаги:

1. **Проверьте спецификацию.**
   Copilot покажет текущее состояние (*current state*) и предлагаемое состояние (*proposed state*) репозитория. Отредактируйте текст, если задача была понята неверно.

2. **Отредактируйте план.**
   В секции плана будут перечислены шаги: какие файлы изменить, какие создать, какие зависимости добавить. Допишите или удалите шаги обычным текстом.

3. **Запустите реализацию.**
   Нажмите кнопку **Implementation** — Copilot сгенерирует изменения в файлах и покажет диффы.

4. **При необходимости — откройте Codespace.**
   Нажмите **Open in Codespace** прямо из Workspace, чтобы вручную отредактировать код, запустить тесты и т.д.

## Как зафиксировать изменения

Когда результат вас устраивает:

1. Нажмите **Create pull request** или **Push to new branch** прямо в Workspace — он автоматически создаст ветку или PR с сгенерированным кодом.
2. Если у вас есть права на запись в репозиторий, можно также запушить в текущую ветку, но рекомендуется использовать PR для сохранения истории изменений и code review.
